## Act

Starts the action named `action` at the actor in `in-target` (none allowed) through the pawn's IADSKActionPerformer (else its controller's), and ends when the performer reports the action's end. Fails when nothing performs actions or the action does not start; leaving the node stops it.

Use it well:

- One node for attacks, shots and abilities: the pawn knows how, the file decides when.
- An action that lasts until it is left (firing) never ends by itself: bound it with `TimeLimit` or run it beside another lane.
- A target slot that names another actor while it runs is passed to RetargetAction.

## Cooldown

Fails at once until `duration` seconds have passed since its child last ended (cancelled included); otherwise runs the child and ends with it. A restart forgets the cooldown.

Use it well:

- Rate-limit an action (a special attack at most every 8 s): while cooling down it fails at once, so a `Selector` falls through to the next option.
- As an option of a `ReactiveSelector` it interrupts the later option running when it becomes ready: "attack the moment the cooldown is over".
- The timer lives in the node's state and is forgotten when the instance restarts.

## MoveTo

Path-follows the pawn to `in-goal` within `acceptanceRadius`, re-pathing when the slot moves farther than `repathDistance` (0: never). ## Parallel

Runs every child at once, each in its own lane (at most 8). Succeeds once `success` children succeeded (`all`, `any` or a count); fails once `failure` failed, or success can no longer be reached. Then cancels the children still running.

Use it well:

- Several things that must all happen, or the first of several that works: move, reload and wait at least 1.5 s (`success="all"`), or whichever of two routes arrives first (`success="any"`).
- A child that ends stays ended; nothing loops. To loop something beside a main task, `SimpleParallel` says it.
- By default one failure fails it and cancels the rest; `failure="all"` keeps going until every child has failed.

Kind: concurrent. Children: 2..8. Schema version: 1.

## ReactiveSelector

A Selector that, every tick, re-checks each earlier option that can be checked (a Guard's condition, a Cooldown being ready, a node with OnCheck); one that turns true cancels the running option and starts in its place. Succeeds at the first success; fails when every option failed.

Use it well:

- Priorities that must interrupt a running lower option (evade interrupts attack): make each earlier option a `Guard`.
- Re-checked options: `Guard`s (their condition), `Cooldown`s (ready again) and project nodes with an `OnCheck`; an earlier option of any other kind is not.
- The conditions are re-checked every tick; keep them to slot comparisons.

Kind: selector. Children: 1..64. Schema version: 1.

Fields: none

Ports: none

## Retry

Runs its child again after each failure. Succeeds when the child succeeds; fails after `count` failed attempts (0: never).

Use it well:

## Selector

Tries its children in order. Succeeds as soon as one succeeds; fails when the last one fails.

Use it well:

- Fallbacks: the preferred option first, cheaper ones after.
- It does not look back: an earlier option that becomes possible again is not retried until the selector restarts. Use `ReactiveSelector` with `Guard` options when it must be.
- Choosing between modes (fight or flee) belongs in the state machine, not in a tree (concept.md: state is the mode, tree is the procedure).

Kind: selector. Children: 1..unbounded. Schema version: 1.

Fields: none

Ports: none

- For "try this, else that" use `Selector`.

Runs its child; fails, cancelling it, once it has run `duration` seconds, drawn once per start from `duration +/- deviation` (floored at 0). Otherwise ends with the child.

Use it well:

- Bound anything that waits on the world (a move, a query, an animation callback), so a missed callback fails the node instead of holding the state.
- When time runs out it cancels the child and fails; handle tree.failure.
- To do something that never ends on its own for a while (fire for 1-3 s), wrap it with `deviation` in a `ForceSuccess`.

Kind: composite. Children: 1..1. Schema version: 1. Thread-safe (may tick on a worker).

| Field | Type | Default |
|---|---|---|
| `deviation` | Float | `0.0` |
| `duration` | Float | `1.0` |

Ports: none

## UtilitySelector

Tries its options highest score first (`Score` scopes; an option scoring 0 or less is skipped, none left fails). With `reevaluate` seconds it scores again and switches when another option wins by more than `margin`.

Use it well:

- Pick the best of several options by score: one `Score` scope per option, fed by Inputs the host publishes.
- With `reevaluate` it switches only when another option wins by more than `margin`, so it does not flap.
- An option scoring 0 or less is skipped; when every one is, it fails.

Kind: selector. Children: 1..64. Schema version: 1.

| Field | Type | Default |
|---|---|---|
| `margin` | Float | `0.0` |
| `reevaluate` | Float | `0.0` |

Ports: none

## Wait

Waits `duration` seconds of tick time, drawn once per start from `duration +/- deviation` (floored at 0). Always succeeds.

Use it well:

- A pause in tick time; `deviation` adds variety from the seeded stream, so a replay matches.
- It never fails, so a tree of `Wait`s alone cannot end with tree.failure.
- Waiting for something to happen is a `Guard` or an event, not a `Wait` in a loop.

Kind: leaf. Children: 0..0. Schema version: 1. Never fails. Thread-safe (may tick on a worker).

| Field | Type | Default |
|---|---|---|
| `deviation` | Float | `0.0` |
| `duration` | Float | `1.0` |

Ports: none
